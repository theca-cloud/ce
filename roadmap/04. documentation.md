# Step 04: Documentation

Goal: the two documents a newcomer reads. `README.md` presents Theca (what it is, what it looks like, why it rather than another); `SELF-HOSTING.md` runs it, from an empty folder to backups and upgrades. Everything they say was tried: the compose and examples by CI (steps 02, 03), the rest by hand in this step (`rclone bisync`, a restore).

## `README.md`: the project's page

- **What Theca is**, in a few lines: self-hosted cloud storage (Nextcloud and Seafile's ground), files deduplicated in chunks on your disk or S3, a web app, a WebDAV drive, organizations with their own libraries, OIDC, version history, trash. From `../docs/features.md`'s V1, said for a user, not a developer.
- **Screenshots** (`screenshots/*.png`, below): the file browser, a file's versions, a preview, an organization's page, the admin's.
- **Quickstart**: three lines and a link to `SELF-HOSTING.md`.
- **Status**: beta until 1.0 (an upgrade may mean starting over, `SELF-HOSTING.md`); the editions in one line (CE: AGPL, everything here; SaaS and EE later).
- The links that stay: docs, contributing, license.

## `SELF-HOSTING.md`: running it

1. **What you need**: Docker with Compose, a domain with HTTPS through a reverse proxy (**required**: the web app's downloads use a Service Worker, which browsers only allow on HTTPS; `localhost` is the exception for trying it), the disk for the files.
2. **Install**: the release's `docker-compose.yml`, `.env` with `PUBLIC_URL`, the secrets' commands (what each is for, why files, the modes), `docker compose up -d`, the setup link from `docker compose logs theca`, the wizard (the storage at `/data/files`).
3. **The reverse proxy**: what it must do (HTTPS, no body size limit, long requests, `X-Forwarded-For` and `TRUSTED_PROXIES`); `examples/caddy/` and `examples/traefik/`, and nginx's two lines for those with one already.
4. **S3 storage**: why (another disk, another machine, a provider), the CORS rule, `examples/s3-garage/`.
5. **Logging in with OIDC**: instance-wide providers and organizations' providers (what each session reaches: decisions.md, Authentication), `examples/authelia/`.
6. **A private CA**: a server reaching a Garage or an IdP behind certificates from your own CA trusts it with `SSL_CERT_FILE` (tested in CI with the test's CA).
7. **Email**: SMTP in the admin's settings (registration, invitations, password resets need it).
8. **WebDAV and sync**: the drive's address and app passwords; Finder, Windows, Linux file managers, phones' file apps; **two-way sync with `rclone bisync`** (V1's sync: the config, the first `--resync`, a timer, what it does with conflicts and deletions, its lock file). Tried end to end against a local compose, with `rclone/rclone`'s image.
9. **Backups and restore**: what to keep (the database with `pg_dump`, the files volume or the bucket, `secrets/` with `data.key`), the commands, a restore tried once into an empty folder.
10. **Upgrades**: before 1.0, read the release notes, an upgrade may mean starting over (the schema is still rewritten); after 1.0, pull and restart, migrations at startup. Postgres majors: `pg_upgrade`, not a pull.
11. **Troubleshooting**: the errors a first install meets (a secret missing or empty, the collation, `PUBLIC_URL` unset, the setup link lost: a restart prints a new one, uploads failing behind a proxy).

The compose's header comment shrinks to the four secret commands and a link here.

## Screenshots (`scripts/screenshots.sh`)

Taken by a script, retaken at releases:

1. `scripts/smoke.sh --keep`: the image just built, set up, a session in `.smoke/cookies`.
2. **Demo data** through the API and WebDAV: organizations ("Acme", a personal space), libraries ("Documents", "Photos", "Projects") with folders and files named as a real person's, versions with messages, a few items in the trash, an image and a Markdown file for previews.
3. The session's cookie as a Playwright storage state; **`npx playwright@<web's version> screenshot`** of each page (1440×900, light), into `screenshots/`. No Node project here: `npx` fetches the CLI, the same version as `web`'s tests.
4. Down, as the smoke test leaves.

Only pages reachable by URL (the CLI loads a page and shoots it): enough for a listing, a file's page, previews, the settings pages. A screenshot needing a click (a menu, a dialog) waits until it's worth a Playwright script.
