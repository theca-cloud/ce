# Step 03: Examples

Goal: `examples/`, what goes around the compose: S3 with Garage, a reverse proxy (Caddy or Traefik), OIDC with Authelia. Each is an overlay on `docker-compose.yml` (`docker compose -f docker-compose.yml -f <overlay>.yml`), with its files and a short README; `SELF-HOSTING.md` (step 04) explains the concepts and links to them.

**One layout for every example**: its files go **next to `docker-compose.yml`** (Compose resolves an overlay's relative paths from the first file's folder), its secrets in the same `./secrets/`. The README says which files to copy and which secret commands to run, like the compose's header.

## `examples/s3-garage/`

```
compose.s3.yml   Garage, its init, the S3 secrets for theca
garage.toml      the node's configuration, no secret in it
garage-init.sh   layout, bucket, key, CORS rule; idempotent
README.md
```

- **Garage single node** (`dxflrs/garage:v2.x`, `core`'s dev version), its metadata and data on named volumes. Its secrets are files like the others: `garage.toml` reads `rpc_secret_file` and `admin_token_file` (`./secrets/garage_rpc_secret`, `garage_admin_token`).
- **The S3 key is the self-hoster's, generated like the other secrets** (`GK` + 24 hex characters, and a 64-hex secret: `./secrets/s3_access_key`, `s3_secret_key`), then **imported** into Garage by the init (the admin API's `ImportKey`). Nothing writes a secret: the init reads them, Theca reads them (mounted into `theca` as secrets: the wizard's key files are `/run/secrets/s3_access_key` and `s3_secret_key`).
- **`garage-init.sh`**, run by a one-shot `garage-init` service (`alpine`, with `curl` and `jq`; Garage's image has no shell), `theca` depending on its success:
    1. The admin API (`/v2/...`, the admin token): the node's ID, its layout role (zone, capacity) and the layout applied if it has none.
    2. The bucket `theca`, the key imported, the key allowed read and write on it.
    3. **The CORS rule**, through the S3 API (`PUT /theca?cors`, signed with `curl --aws-sigv4`, the key's credentials): `PUT` and `GET` from `PUBLIC_URL`, the headers `x-amz-checksum-sha256` and `If-None-Match`, `ETag` exposed (decisions.md, the web app's CORS). Rewritten at every start: changing `PUBLIC_URL` updates it.
    Every step checks first, so a restart changes nothing.
- **Garage needs its own public origin** (`S3_URL`, e.g. `https://s3.example.com`, in `.env`): browsers reach presigned URLs directly, a path prefix on the app's origin would break their signatures, and the server reaches Garage at that same URL (the storage's one `host`). So the reverse proxy serves it too (the proxy examples do). Region `garage`, `path_style` on (the wizard's default).
- **In `core`**: the CORS rule documented in `CONFIGURATION.md`, Storage backends (for anyone bringing their own S3), a `docs(core)` commit.

**CI**: the smoke test a second time with the overlay, in a folder laid out as a self-hoster's (`.smoke/project/`: the compose, the example's files, `secrets/`), the S3 URL `http://garage:3900` (curl reaching it through `--connect-to`, as for the app). The setup creates the S3 storage; the WebDAV file goes through Garage; then **the CORS rule**: a preflight (`OPTIONS`, `Origin: PUBLIC_URL`, `PUT` with the two headers) answers `Access-Control-Allow-Origin`, and a `GET` exposes `ETag`. The presigned flow itself is `core`'s, tested there against Garage.

## `examples/caddy/` and `examples/traefik/`

The proxy in Docker, in the compose's network, with HTTPS from Let's Encrypt:

- **`compose.caddy.yml`** and a `Caddyfile`: `{$DOMAIN}` to `theca:8080`; with S3, `{$S3_DOMAIN}` to `garage:3900` (a second block, commented out until wanted).
- **`compose.traefik.yml`**: labels on `theca` (and `garage`), the ACME resolver. **The entrypoint's `readTimeout` raised** (Traefik's default ends a request after 60 s: a large WebDAV `PUT` is cut).
- Both: `ports: !reset []` on `theca` (only the proxy publishes, 80 and 443); a fixed subnet for the compose's network, so `TRUSTED_PROXIES` names it.
- No body size limit to lift in either (none by default), said in the README since it's the first thing other proxies (nginx's 1 MB) get wrong.

**CI**: `docker compose config -q` on each (a broken file fails); certificates need a real domain, tried by hand.

## `examples/authelia/`

Authelia as the instance's OIDC provider:

- **`compose.authelia.yml`** and `configuration.yml`: Authelia (its own domain through the proxy, `AUTH_DOMAIN`), a file of users (`users.yml`, one example user, its password hashed with `authelia crypto hash generate`), its secrets as files (`AUTHELIA_*_FILE`: session, storage encryption, the OIDC HMAC and the JWKS key, generated with `openssl`).
- **The order**, from the README: create the provider in Theca's admin pages first (issuer `https://auth.example.com`, client ID `theca`, client secret file `/run/secrets/oidc_client_secret`, mounted into `theca`), copy the callback URL it shows (`/api/v1/auth/oidc/{provider}/callback`, its ID in it), put it in Authelia's client (`redirect_uris`, with the secret's hash), restart Authelia.
- The client: `authorization_code` with PKCE (`S256`), scopes `openid email profile`, `token_endpoint_auth_method: client_secret_basic`.

**CI**: `docker compose config -q`; tried by hand behind one of the proxies.

## `scripts/ci.sh`

`docker compose config -q` on the compose alone and with each overlay (dummy secret files, `PUBLIC_URL`, the domains), then the smoke test, then the smoke test with S3. The smoke test grows a mode (`scripts/smoke.sh --s3`) rather than a second script.

## To verify while building

- Garage v2's admin API: `ImportKey`, layout without the CLI, and `PutBucketCors` through its S3 API (its compatibility list says supported).
- `curl --aws-sigv4` against Garage, `Content-MD5` if `PutBucketCors` wants it.
- Authelia's current client schema (it changes between minors).

## Done when

- `scripts/ci.sh` passes locally and in CI, S3 included.
- By hand, on a machine with a domain: Caddy or Traefik with HTTPS, a file uploaded from the browser to Garage (presigned, CORS), a login through Authelia.
